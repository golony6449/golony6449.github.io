# 30장 노이즈와 필터: 흔들리는 값을 다루는 법

## 이 장에서

센서 값이 흔들린다. rpm이 1,200과 1,180을 오가고, 냉각수가 91.8°C와 92.1°C를 반복하고, 가끔 5,000rpm 같은 값이 튄다. 웹 개발자는 이 상황을 안다. 버튼 디바운스, API 지연의 롤링 평균, 로드 밸런서의 EWMA, 알람 중복 제거가 모두 같은 문제다. **원본은 그대로 두고, 보여 주거나 판단할 때만 부드럽게 만든다.**

이 장의 흐름은 다음과 같다.

```text
원본 표본 → 필터(이동 평균·EMA·중앙값·저역 통과) → 사용(표시·제어·알람)
                 │
                 └─ 지연·왜곡이라는 비용
```

웹과 대응시키면 다음과 같다.

| 웹 | 센서 데이터 |
|---|---|
| 디바운스 | 중앙값·확인 시간 |
| 스로틀(throttle) | 샘플링 주기 제한 |
| 롤링 평균 지표 | 이동 평균 |
| EWMA 로드 밸런싱 | 지수 이동 평균 |
| p95·중앙값 지연 | 중앙값 필터 |
| 알람 중복 제거 | 히스테리시스·지속 시간 |

이 장에서 다루는 것:

- 노이즈·이상값·바이어스·지연을 구분하기
- 이동 평균, 지수 이동 평균(EMA), 중앙값 필터, 1차 저역 통과 필터
- 필터의 지연(위상 지연)이라는 비용
- 고정소수점으로 EMA를 구현하는 법
- 칼만 필터 1차원 예시로 보는 직관
- 같은 합성 신호에 필터를 적용해 비교하기
- PC에서 컴파일·실행한 펌웨어용 C 구현

## 30.1 노이즈·이상값·바이어스·지연을 구분한다

필터를 고르기 전에 무엇을 없애려는지 정해야 한다. 센서 값의 흔들림에는 여러 원인이 섞여 있다.

| 현상 | 모양 | 예 | 대응 |
|---|---|---|---|
| 랜덤 노이즈 | 평균 주위로 계속 흔들림 | ADC 잡음, 열잡음 | 평균·EMA·저역 통과 |
| 바이어스 | 일정하게 치우침 | 캘리브레이션 오차, 오프셋 | 보정(필터 아님) |
| 스파이크 | 한두 표본만 크게 튐 | EMI, 통신 오류, 순간 접촉 불량 | 중앙값·범위 검사 |
| 양자화 | 일정 간격으로 계단 | ADC LSB, 1°C 해상도 | 분해능 확인, 필요하면 오버샘플링 |
| 지연 | 값이 늦게 따라옴 | 필터, 통신, ECU 처리 | 지연 예산에 포함 |

- **바이어스는 필터로 고칠 수 없다.** 평균을 내도 치우친 값은 치우친 채로 남는다. 데이터시트·기준기와 비교해 보정한다.
- **스파이크는 평균 필터가 오히려 퍼뜨린다.** 한 표본의 큰 값이 N개 표본에 나눠져 들어간다. 중앙값 필터가 낫다.
- **지연은 필터의 대가다.** 부드럽게 만들수록 실제 변화에 늦게 반응한다. 알람·제어에서는 이 지연을 예산에 넣어야 한다.

5장에서 본 ADC 분해능도 노이즈의 한 종류다. 12비트 ADC, 3.3V 기준이면 1 LSB는 `3.3V / 4095 ≈ 0.806mV`다. 이보다 작은 변화는 숫자로 표현되지 않는다. 필터를 아무리 잘 만들어도 **없는 분해능을 만들 수는 없다.**

## 30.2 이동 평균

가장 단순한 필터다. 최근 N개 표본의 평균을 낸다.

```text
y[n] = (x[n] + x[n-1] + ... + x[n-N+1]) / N
```

- N이 크면 더 부드러워지지만 더 늦는다.
- 백색 잡음(white noise)을 가정하면 잡음은 대략 `√N`분의 1로 줄어든다. N=5면 약 2.24배, N=16이면 4배다. (Smith, *The Scientist and Engineer's Guide to DSP*, 원서 15장)
- 인과적(causal) 이동 평균의 지연은 대략 `(N-1)/2` 표본이다. 10Hz에서 N=5면 `2 × 0.1s = 0.2s`다.
- 시작 구간에서는 창이 덜 차므로 평균이 흔들린다. 첫 N개는 `count`로 나누거나, 초기값으로 채운다.

| N(10Hz) | 지연 | 잡음 감소(이론) | 메모리 |
|---:|---:|---:|---:|
| 3 | 0.10s | 1.73배 | 3 |
| 5 | 0.20s | 2.24배 | 5 |
| 11 | 0.50s | 3.32배 | 11 |
| 21 | 1.00s | 4.58배 | 21 |

- `√N`은 표본이 서로 독립인 백색 잡음일 때의 이론값이다. 실제 센서 잡음은 상관되어 있어 감소가 더 작을 수 있다.
- 이동 평균은 계단 응답을 **비스듬하게** 만든다. 급격한 변화가 여러 표본에 걸쳐 번진다. 스파이크 제거에는 불리하다.
- 구현은 링 버퍼와 합계를 유지하면 표본당 O(1)이다. 매번 N개를 더하면 O(N)이 된다.

## 30.3 지수 이동 평균(EMA)

EMA는 최근 값에 더 큰 가중치를 주면서, 과거 값의 영향을 지수적으로 줄인다.

```text
y[n] = y[n-1] + α × (x[n] - y[n-1])
     = (1 - α) × y[n-1] + α × x[n]
```

- `α`는 0보다 크고 1 이하다. 작을수록 부드럽고 늦다.
- 메모리는 현재 값 하나면 된다. 이동 평균처럼 N개를 저장하지 않는다.
- 초기값은 보통 첫 표본(`y[0] = x[0]`)으로 둔다. 초기 과도 상태가 끝날 때까지는 신뢰하지 않는다.
- α=1이면 필터가 없다. α가 0에 가까우면 거의 움직이지 않는다.

### 시상수와 차단 주파수

EMA의 시상수 τ는 다음과 같다.

```text
τ = -Ts / ln(1 - α)     (정확)
τ ≈ Ts / α              (α가 작을 때 근사)
```

10Hz(`Ts = 0.1s`)에서:

| α | τ(정확) | τ/Ts | 계단 63.2% 도달(실측) |
|---:|---:|---:|---:|
| 0.1 | 0.949s | 9.49 | 0.9s |
| 0.2 | 0.448s | 4.48 | 0.4s |
| 0.5 | 0.144s | 1.44 | 0.1s |

저역 통과 관점에서 차단 주파수 `fc`와 α의 관계는 다음과 같다. (Smith, 원서 19장의 단일 극 필터 계수와 같은 식이다.)

```text
α = 1 - exp(-2π × fc × Ts)
fc = -ln(1 - α) / (2π × Ts)
```

- `fc`는 "이 주파수까지 통과시키겠다"는 설계값이다. 실제로는 `fc`에서 이미 진폭이 약 0.707배로 줄고 위상이 45° 늦는다.
- α가 작으면 `α ≈ 2π fc Ts`로 근사할 수 있다.
- EMA와 1차 저역 통과 필터는 **같은 필터**다. α로 설계하면 시간 영역, `fc`로 설계하면 주파수 영역이 기준이 된다.

### 고정소수점 EMA

펌웨어에서 float를 피하려면 α를 정수로 양자화한다. α를 1/256 단위로 표현하면 `alpha_q8 = round(α × 256)`이고, 갱신은 다음과 같다.

```c
int32_t ema_update(int32_t y, int32_t x, int32_t alpha_q8)
{
    int32_t diff = x - y;
    int32_t prod = diff * alpha_q8;
    int32_t step = (prod + (prod >= 0 ? 128 : -128)) / 256;
    return y + step;
}
```

- `+128 / -128`은 반올림이다. 단순히 `>> 8`을 쓰면 음수에서 반올림 방향이 구현에 따라 달라질 수 있다.
- `diff × alpha_q8`의 범위를 확인한다. 16비트 센서 값(0~65,535)과 α≤1이면 `65,535 × 256 ≈ 16.8M`으로 int32에 들어간다.
- α=0.2는 `alpha_q8 = 51`(51/256 ≈ 0.1992)이다. α=0.1은 26, α=0.5는 128이다.
- 초기값 `y = x[0]`을 넣고, 첫 몇 표본은 버리거나 `warmup`으로 표시한다.

C 구현과 실행 결과는 30.8절에 모았다.

## 30.4 중앙값 필터

중앙값 필터는 창 안의 값을 정렬해 가운데 값을 고른다.

```text
y[n] = median(x[n], x[n-1], ..., x[n-N+1])
```

- 창 크기 3, 5, 7처럼 **홀수**를 주로 쓴다. 짝수면 가운데 두 값의 평균을 내거나 한쪽을 고르는 규칙을 정해야 한다.
- 한두 개의 스파이크를 잘 제거한다. 창의 절반 이상이 정상 값이면 스파이크는 중앙값에 영향을 주지 못한다.
- 계단(step) 가장자리를 비교적 잘 보존한다. 이동 평균처럼 급격한 변화를 비스듬하게 만들지 않는다.
- 선형 필터가 아니므로 주파수 응답으로 설명하기 어렵다. "어떤 주파수를 자른다"기보다 "순위로 고른다"고 이해한다.
- 창이 크면 정렬 비용이 커진다. N=5면 삽입 정렬로 충분하지만, N=31을 매 표본 정렬하면 MCU에서 부담이 된다.
- 인과적 구현에서는 창이 과거만 보므로 `(N-1)/2` 표본의 지연이 있다. 오프라인 분석에서 창을 중심에 두면 지연이 0이지만, 실시간 펌웨어에서는 불가능하다.

## 30.5 1차 저역 통과 필터와 위상 지연

RC 저역 통과 회로는 저항과 커패시터로 만든다.

```text
τ = R × C
fc = 1 / (2π × R × C)
|H(f)| = 1 / √(1 + (f/fc)²)
φ(f) = -arctan(f / fc)
```

- `fc`에서 진폭은 `1/√2 ≈ 0.707`(-3dB), 위상은 -45°다.
- `fc`보다 높은 주파수는 대략 -20dB/decade로 줄어든다. 1차 필터라 차수가 낮다.
- 저주파에서는 위상 지연이 대략 `τ`에 해당한다. `fc`에서의 지연은 `1/(8fc)`다.
- 디지털 구현은 EMA와 같다. `α = 1 - exp(-2π fc Ts)`.

### 지연은 공짜가 아니다

냉각수 알람을 0.2Hz 저역 통과 필터로 부드럽게 만들었다고 하자. 신호가 0.2Hz라면 필터는 그 주파수에서 **45° 늦고 진폭을 0.707배로 줄인다.** 0.2Hz의 주기는 5초이므로 45°는 약 0.625초다. "110°C 초과 5초 지속" 알람에 0.6초 지연이 더해지면 판정이 달라질 수 있다.

- **표시용 필터**는 지연이 눈에 덜 띈다. 그래프가 부드러워지면 보기 좋다.
- **제어·알람용 필터**는 지연을 예산에 넣어야 한다. 필터 지연 + 통신 지연 + 판정 주기를 합쳐 요구 시간을 만족하는지 확인한다.
- **안전 관련 신호**는 OBD 대시보드의 필터에 의존하지 않는다. 차량 ECU의 경고와 직접 센서를 신뢰한다. 11장의 원칙이 그대로 적용된다.
- 원본을 저장하고, 필터를 적용한 값에는 `filter` 이름과 파라미터를 붙인다. 나중에 "왜 알람이 늦었나"를 재현할 수 있어야 한다.

## 30.6 칼만 필터 1차원 직관

칼만 필터는 "모델의 예측"과 "측정값"을 uncertainty(불확실성)에 따라 섞는다. 1차원이면 다음 네 줄이 전부다.

```text
예측:
  x = x                 (상태는 그대로, 또는 모델로 이동)
  P = P + Q             (불확실성 증가)

갱신:
  K = P / (P + R)       (칼만 이득)
  x = x + K × (z - x)   (측정 z로 보정)
  P = (1 - K) × P       (불확실성 감소)
```

- `P`는 상태 추정의 분산, `Q`는 과정 잡음(모델이 틀릴 정도), `R`은 측정 잡음의 분산이다.
- `K`가 1에 가까우면 측정을 믿고, 0에 가까우면 모델을 믿는다.
- `R`이 크면(센서가 시끄러우면) `K`가 작아져 측정을 덜 따른다. `Q`가 크면(모델을 못 믿으면) `P`가 커져 `K`가 커진다.
- 정상 상태에서 `K`는 일정해진다. 위 예(10Hz, Q=0.01, R=4, P0=1)에서 `K ≈ 0.049`로 수렴했다.

Python 예:

```python
Q, R, P, x = 0.01, 4.0, 1.0, z[0]
for measurement in z:
    P += Q
    K = P / (P + R)
    x += K * (measurement - x)
    P *= (1 - K)
```

- 같은 합성 신호에서 측정 잡음 표준편차 2.0일 때 RMSE가 1.99에서 0.40으로 줄었다. 다만 이 예는 모델을 강하게 믿는 설정이라 **느린 변화에 지연**이 생긴다.
- 칼만 필터는 선형·가우시안 가정에서 최적이다. 스파이크에는 약하다. 큰 스파이크 하나가 추정값을 끌고 갈 수 있으므로, 먼저 범위 검사·중앙값 필터로 이상값을 걸러 낸다.
- 차량 온도처럼 모델이 단순한 값에는 유용하지만, 상태 전환이 많은 값(기어, 시동)에는 맞지 않는다. 모델이 틀리면 필터는 자신 있게 틀린 값을 낸다.

## 30.7 같은 신호에 적용해 비교

다음 합성 신호를 만들었다. 10Hz, 60초, 600표본이다.

```text
clean = 80 + 8×sin(2π×0.2t) + 3×sin(2π×0.02t)
noisy = clean + N(0, 1.5²)
spike: 120번째 +20, 300번째 -18, 450번째 +15
```

필터는 이동 평균(5), 중앙값(5), EMA(α=0.2), 1차 저역 통과(`fc=0.2Hz`)를 적용했다. "정렬 후 RMSE"는 측정된 지연만큼 출력을 앞당겨 비교한 값이다.

| 필터 | RMSE | 정렬 후 RMSE | 스파이크 오차 | 지연 |
|---|---:|---:|---:|---:|
| 원본 | 1.86 | 1.86 | 16.23 | 0.00s |
| 이동 평균(5) | 1.79 | 0.91 | 4.19 | 0.20s |
| 중앙값(5) | 0.89 | 0.89 | 1.10 | 0.00s |
| EMA(α=0.2) | 2.65 | 0.92 | 3.89 | 0.40s |
| 1차 LPF(fc=0.2Hz) | 3.83 | 1.65 | 3.53 | 0.60s |

- **중앙값**이 이 신호에서 가장 좋다. 스파이크를 없애고 지연도 없다(오프라인 중심 창). 실시간 인과 구현에서는 창 크기에 따른 지연이 생긴다.
- **이동 평균**은 잡음을 줄이지만 스파이크를 5개 표본에 퍼뜨린다. 스파이크 오차 4.19가 그 결과다.
- **EMA**는 정렬 후 RMSE가 0.92로 좋아지고, **LPF**는 1.65로 개선되지만, 지연이 각각 0.4초·0.6초다. 정렬하지 않은 RMSE만 보면 원본보다 나빠 보인다.
- **LPF(fc=0.2Hz)**는 신호의 0.2Hz 성분을 정확히 차단 주파수에 두어 진폭을 줄인다. 정렬 후 RMSE가 1.65로 다른 필터보다 나쁘다. 필터의 차단 주파수를 신호 대역과 겹치게 잡으면 정보가 손실된다.

이 비교의 교훈은 **"RMSE가 낮은 필터가 좋은 필터"가 아니라는 것**이다. 목적이 스파이크 제거인지, 잡음 감소인지, 지연 최소화인지에 따라 선택이 달라진다. 알람에는 지연 예산을, 표시에는 부드러움을, 제어에는 안정성을 우선한다.

### 비교 코드

```python
import numpy as np

fs, dt = 10.0, 0.1
t = np.arange(0.0, 60.0, dt)
clean = 80 + 8*np.sin(2*np.pi*0.2*t) + 3*np.sin(2*np.pi*0.02*t)
rng = np.random.default_rng(42)
noisy = clean + rng.normal(0, 1.5, len(t))
spikes = [120, 300, 450]
noisy[spikes] += np.array([20.0, -18.0, 15.0])

def ema(x, alpha):
    y = np.empty_like(x)
    y[0] = x[0]
    for i in range(1, len(x)):
        y[i] = y[i-1] + alpha*(x[i] - y[i-1])
    return y

def moving_average(x, n):
    return np.array([x[max(0, i-n+1):i+1].mean() for i in range(len(x))])

def median_filter(x, n):
    h = n//2
    return np.array([np.median(x[max(0, i-h):i+h+1]) for i in range(len(x))])

filters = {
    "MA(5)": moving_average(noisy, 5),
    "median(5)": median_filter(noisy, 5),
    "EMA(0.2)": ema(noisy, 0.2),
    "LPF(0.2Hz)": ema(noisy, 1 - np.exp(-2*np.pi*0.2/fs)),
}
for name, y in filters.items():
    rmse = np.sqrt(np.mean((y - clean)**2))
    print(name, round(float(rmse), 2))
```

실행 환경은 2026-10-30, numpy 2.5.4다. 지연은 상호상관으로 측정했고, 표의 값은 그 실행 결과다.

## 30.8 펌웨어용 C 구현

다음 코드는 PC에서 컴파일·실행해 확인했다. EMA, 이동 평균, 중앙값 필터를 한 파일에 두고, 5,000이라는 스파이크가 들어온 뒤의 출력을 비교한다.

```c
#include <stdint.h>
#include <stdio.h>

static int32_t ema_update(int32_t y, int32_t x, int32_t alpha_q8)
{
    int32_t diff = x - y;
    int32_t prod = diff * alpha_q8;
    int32_t step = (prod + (prod >= 0 ? 128 : -128)) / 256;
    return y + step;
}

#define MA_N 5
typedef struct {
    int32_t buf[MA_N];
    int32_t sum;
    uint8_t idx;
    uint8_t count;
} MovAvg;

static int32_t ma_update(MovAvg *m, int32_t x)
{
    if (m->count == MA_N) {
        m->sum -= m->buf[m->idx];
    } else {
        m->count++;
    }
    m->buf[m->idx] = x;
    m->sum += x;
    m->idx = (uint8_t)((m->idx + 1) % MA_N);
    return m->sum / m->count;
}

static int32_t median5(const int32_t in[5])
{
    int32_t a[5];
    int i, j;
    for (i = 0; i < 5; i++) a[i] = in[i];
    for (i = 1; i < 5; i++) {
        int32_t key = a[i];
        j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
    return a[2];
}

int main(void)
{
    const int32_t in[] = {1000, 1000, 1000, 1000, 1000, 5000, 1000, 1000, 1000, 1000};
    const int n = (int)(sizeof(in) / sizeof(in[0]));
    int32_t y = in[0];
    MovAvg ma = {{0}, 0, 0, 0};
    int32_t hist[5] = {in[0], in[0], in[0], in[0], in[0]};
    double yf = (double)in[0];
    int i;

    printf("i raw   ema_q8 ema_float ma5  med5\n");
    for (i = 0; i < n; i++) {
        y = ema_update(y, in[i], 51);
        yf += (51.0 / 256.0) * ((double)in[i] - yf);
        for (int k = 0; k < 4; k++) hist[k] = hist[k + 1];
        hist[4] = in[i];
        printf("%d %5d %6d %9.2f %4d %4d\n", i, in[i], y,
               yf, ma_update(&ma, in[i]), median5(hist));
    }
    return 0;
}
```

- 고정소수점 EMA는 float EMA와 1 카운트 이내로 일치한다. 51/256 ≈ 0.1992라서 float 0.2와 완전히 같지는 않다.
- 중앙값 필터는 스파이크를 즉시 제거한다. 이동 평균은 5개 표본에 걸쳐 1,800으로 끌어올린다.
- EMA는 스파이크의 영향을 여러 표본에 남긴다. 1797 → 1638 → 1511 → 1409 → 1328로 지수적으로 줄어든다.

### 자원과 함정

| 구현 | 메모리 | 표본당 연산 | 지연 | 비고 |
|---|---|---|---|---|
| EMA | 4~8바이트 | 곱셈 1, 나눗셈 1 | τ | 가장 가벼움 |
| 이동 평균 | N×4바이트 + 합계 | 덧셈·뺄셈 2, 나눗셈 1 | (N-1)/2 표본 | 합계 오버플로 확인 |
| 중앙값(5) | 5×4바이트 | 비교·이동 약 10~20회 | (N-1)/2 표본(인과) | N이 크면 비쌈 |

- **합계 오버플로**: 이동 평균의 `sum`이 int32일 때 `N × 최대값`이 2³¹을 넘지 않는지 확인한다. 16비트 ADC(0~65,535)와 N=5면 327,675로 안전하다.
- **나눗셈 0**: `count`가 0일 때 나누지 않는다. 초기값을 넣거나 첫 표본을 그대로 반환한다.
- **alpha_q8 경계**: 0이면 필터가 멈추고, 256이면 필터가 없다. 설정값을 검증한다.
- **부호 있는 시프트**: `>>`는 음수에서 구현 정의다. 이식성을 위해 나눗셈과 반올림을 쓴다.
- **초기화**: 첫 표본을 `y`에 넣지 않으면 0에서 시작해 한동안 실제 값으로 수렴한다. 초기 과도 구간을 `warmup`으로 표시한다.

### 어디서 필터링할 것인가

| 위치 | 좋은 일 | 나쁜 일 |
|---|---|---|
| 펌웨어(장치) | 빠른 제어, 메모리 절약, 즉시 범위 검사 | 원본 손실, 파라미터 변경 어려움 |

- **필터 파라미터를 기록한다.** α, N, `fc`, 적용 시각을 로그에 남겨야 재현할 수 있다.
- **알람과 표시를 분리한다.** 표시는 부드럽게, 알람은 원본·지속 시간·히스테리시스로 판단한다.

## 30.11 체크리스트

- [ ] 없애려는 것이 노이즈·바이어스·스파이크·지연 중 무엇인지 구분했는가
- [ ] 필터의 지연을 시간 단위로 계산했는가
- [ ] 알람·제어의 지연 예산에 필터 지연을 넣었는가
- [ ] 창 크기와 α를 신호 동특성에 맞췄는가
- [ ] 원본을 보존하고 필터 파라미터를 기록하는가
- [ ] 고정소수점 범위·반올림·초기화를 확인했는가
- [ ] 스파이크에는 중앙값·범위 검사를 먼저 적용했는가
- [ ] 칼만 필터의 모델·Q·R을 설명할 수 있는가
- [ ] 펌웨어·서버·브라우저에서 이중 필터링하지 않는가
- [ ] 실제 차량에서는 정차 상태에서 읽기만 하는가

## 장 요약

- 필터를 고르기 전에 노이즈·바이어스·스파이크·지연을 구분한다. 바이어스는 필터로 고칠 수 없다.
- 이동 평균은 `√N`만큼 잡음을 줄이지만 `(N-1)/2` 표본만큼 늦고, 스파이크를 퍼뜨린다.
- EMA는 메모리 O(1)이고 `τ = -Ts/ln(1-α)`만큼 늦는다. α를 1/256 정수로 양자화해 펌웨어에서 쓸 수 있다.
- 중앙값 필터는 스파이크에 강하고 계단을 보존하지만, 정렬 비용이 들고 선형 주파수 응답이 없다.
- 1차 저역 통과 필터와 EMA는 같은 필터다. `fc`에서 진폭 0.707, 위상 -45°다. 필터링의 대가는 지연이다.
- 칼만 필터는 예측과 측정을 불확실성으로 섞는다. 1차원에서는 네 줄이면 되지만, 모델·Q·R이 틀리면 자신 있게 틀린다.
- 같은 신호 비교에서 중앙값이 스파이크에 가장 강했고, EMA·LPF는 지연을 보정하면 잡음을 줄였다. RMSE만으로 필터를 고르지 않는다.
- C 구현은 PC에서 컴파일·실행해 확인했다. 고정소수점 EMA는 float와 1 카운트 이내로 일치했다.

## 정답과 해설

### 1.

1. `(5-1)/2 × 0.1s = 0.2s`다.
2. `√5 ≈ 2.24`배다. 표본이 독립인 백색 잡음일 때의 이론값이다.
3. 지연은 `(21-1)/2 × 0.1s = 1.0s`, 잡음 감소는 `√21 ≈ 4.58`배다. 지연이 1초로 커지므로 알람·제어에는 부적합할 수 있다.

### 2.

1. `τ = -0.1 / ln(0.9) ≈ 0.949s`다. 표본으로는 약 9.5개다.
2. 63.2% 도달은 약 0.95초다. 이산 구현에서는 9~10번째 표본 근처다.
3. α=0.5면 `τ = -0.1 / ln(0.5) ≈ 0.144s`로 약 6.6배 빨라진다. 대신 잡음 억제는 약해진다.

### 3.

1. `0.2 × 256 = 51.2`이므로 반올림해 51이다. 실제 α는 51/256 ≈ 0.1992다.
2. `diff = 1200 - 1000 = 200`, `prod = 200 × 51 = 10200`, `step = (10200 + 128) / 256 = 10328 / 256 = 40`(정수 나눗셈), `y = 1000 + 40 = 1040`이다.
3. float로는 `1000 + 0.2 × 200 = 1040`이다. 양자화된 α로는 `1000 + 0.1992 × 200 = 1039.84`이므로 정수 결과 1040과 0.16 차이다.

### 4.

1. 창이 `1000, 1000, 1000, 1000, 5000`이므로 정렬하면 `1000, 1000, 1000, 1000, 5000`, 중앙값은 1000이다.
2. `(1000+1000+1000+1000+5000)/5 = 1800`이다.
3. 중앙값이다. 이동 평균은 스파이크를 5개 표본에 퍼뜨려 1800으로 끌어올린다.

### 5.

1. 표시용으로는 짧은 중앙값(3)이나 EMA(α=0.3~0.5, τ≈1~2초)가 무난하다. 알람용으로는 원본에 가까운 값과 지속 시간·히스테리시스를 쓰고, 필요하면 짧은 중앙값만 적용한다. 냉각수는 열용량이 커서 1Hz면 충분하다.
2. 필터의 위상 지연을 시간으로 환산한다. 1차 LPF `fc`에서 지연은 `1/(8fc)`이고, EMA는 `τ`다. 필터 지연 + 폴링 지터 + 판정 주기가 5초 요구에 들어가는지 확인한다. 예를 들어 τ=1초 필터는 5초 지속 판정을 약 1초 늦출 수 있으므로, 임계값을 낮추거나 지속 시간을 보정한다.
3. 안 된다. 표시는 부드러움이 중요하지만 알람은 지연과 누락이 더 중요하다. 같은 원본에서 표시용·알람용 파생 값을 따로 만들고, 알람은 원본·지속 시간·히스테리시스로 판정한다. 안전 관련 경고는 차량 ECU의 경고를 신뢰한다.
