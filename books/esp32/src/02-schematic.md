# 2장 CH343은 없었다: 회로도 읽기

## 2.1 "CH343을 거쳐야 좋은 거 아냐?"

1장에서 포트 이름이 `USB JTAG/serial debug unit`으로 떴다. 칩에 내장된 USB를 쓴다는 뜻이다. 그런데 위키 자료 목록에 CH343 데이터시트가 있었다. 필자는 오히려 걱정이 됐다.

> **질문 노트** — "ch343을 거쳐야 좋은거 아냐?"

이 질문에는 감이 아니라 회로도로 답하기로 했다. 웹으로 치면 **API 문서의 설명보다 실제 라우팅 설정 파일을 보는 것**이다.

## 2.2 회로도 PDF를 직접 읽다

Waveshare 위키 페이지는 자동 요청을 막아서(403) 직접 열 수 없었다. 대신 회로도 PDF(`ESP32-S3-Touch-LCD-4.3B-Sch.pdf`)를 받아, 파이썬 PDF 라이브러리(PyMuPDF)로 글자와 연결 이름(net 이름)을 뽑아 따라갔다. `uv run --with pymupdf`로 설치 없이 실행했다.

USB-C 단자에서 칩까지 신호를 따라간 결과는 이렇다(**문헌 기반**: 회로도).

```text
USB-C D+/D-  →  USBH_N / USBH_P
             →  0Ω 저항 R27 / R28
             →  ESP_USB_N / ESP_USB_P
             →  GPIO19 / GPIO20 (칩 내장 USB)
```

중간에 스위치도, 다른 칩도 없다. **이 보드에는 CH343이 없다.** 위키의 CH343 데이터시트는 여러 보드가 함께 쓰는 공용 자료였다.

> **알게 된 점** — 0Ω 저항은 "전선 대신 놓은 부품"이다. 나중에 경로를 바꿀 수 있도록 남겨 두는 자리다. 코드로 치면 지금은 항등 함수인 미들웨어 슬롯이다.

## 2.3 그럼 UART0은 어디로 가나

ESP32 보드는 보통 첫 번째 UART(UART0, GPIO43/44)를 USB-시리얼 칩에 이어 PC와 통신한다. 이 보드는 다르다.

| 신호 | 연결 |
|---|---|
| GPIO43 `TXD0`, GPIO44 `RXD0` | RS485 트랜시버(SP3485) → 터미널 블록의 RS485 단자 |
| GPIO19/20 | USB-C (칩 내장 USB Serial/JTAG) |

이 사실이 3장에서 그대로 함정이 된다. Arduino의 `Serial`이 UART0으로 나가면, 그 출력은 PC가 아니라 **RS485 단자**로 간다.

## 2.4 CH343이 없어서 잃는 것과 얻는 것

| | 외부 USB-시리얼 칩(CH343 등) | 칩 내장 USB Serial/JTAG (이 보드) |
|---|---|---|
| 자동 리셋 | DTR/RTS 선으로 리셋 회로를 구동 | 칩 안의 USB 장치가 직접 리셋 |
| 디버깅 | 별도 JTAG 장비 필요 | **USB 하나로 JTAG 디버깅 가능** (OpenOCD + GDB) |
| 약점 | — | 펌웨어가 USB를 망가뜨리면 포트가 사라진다 (7장에서 실제로 겪음) |

회로도에는 DTR/RTS로 리셋을 거는 회로도 없었다. 그래서 첫 업로드는 수동으로 다운로드 모드에 넣어야 했다(3장). 하지만 한 번 올린 뒤로는 내장 USB가 알아서 리셋해 주었다(**실측**).

결론적으로 CH343을 거치지 않는 것은 단점이 아니다. 오히려 USB 하나로 단계별 디버깅까지 할 수 있다. 나중에 ESP-IDF로 넘어가면 이 장점을 쓸 생각이다.

## 2.5 회로도 구석의 메모: 전류

회로도에는 이런 메모도 있었다. **화면 혼자 약 550mA를 쓰고, PC의 USB 포트는 500mA를 다 못 줄 수 있다.** 그래서 PC에 꽂아 디버깅할 때는 배터리 스위치를 OFF로 둔다.

> **알게 된 점** — 웹 서버는 전원이 모자라서 죽는 일을 걱정하지 않는다. 임베디드는 "USB 포트가 줄 수 있는 전류"가 설계 조건이다.

## 알게 된 점

- 위키의 자료 목록은 "이 보드에 들어 있는 부품 목록"이 아닐 수 있다. 회로도가 최종 근거다
- 이 보드의 PC 통신은 칩 내장 USB 하나다. UART0은 RS485로 간다
- 내장 USB는 JTAG 디버깅을 공짜로 준다. 대신 펌웨어가 USB를 망가뜨리면 수동 복구가 필요하다
