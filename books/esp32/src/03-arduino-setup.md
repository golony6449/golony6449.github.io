# 3장 최신 대신 확실한 버전: Arduino 환경과 첫 업로드

## 3.1 보드 패키지와 Espressif

Arduino IDE는 보드마다 **보드 패키지**를 따로 설치한다. 컴파일러, 칩 라이브러리, 업로드 도구를 한 묶음으로 담은 것이다. 웹으로 치면 런타임과 SDK, 배포 CLI를 한 번에 담은 툴체인 이미지에 가깝다.

> **질문 노트** — "expressif가 esp32 제조사야?"

맞다. 철자는 **Espressif**다. ESP32 칩을 만든 회사이고, 칩용 공식 개발 프레임워크(ESP-IDF)와 그 위에 얹은 Arduino 코어(`arduino-esp32`)를 함께 관리한다. 보드 매니저에 추가하는 주소도 Espressif 것이다.

```text
https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

## 3.2 4.0이 최신인데 왜 3.0.7인가

보드 매니저를 열자 버전이 여럿 보였다.

| 버전 | 기반 | 비고 |
|---|---|---|
| **4.0.0** | ESP-IDF 6.1 | 2026-11-19 출시. 이 날 기준 나흘 전 |
| **3.3.13** | ESP-IDF 5.5 | 3.x의 최신 |
| **3.0.7** | ESP-IDF 5.1 계열 | Waveshare 위키가 검증한 버전 |

> **질문 노트** — "4.0이 최신인데 이걸로 설치하면 안돼?" / "3.3.13은?"

Waveshare 위키는 3.0.0 이상을 요구하고, 오프라인 설치 패키지도 3.0.7이다. RS485 수신에 문제가 생기면 3.0.7로 내리라는 안내까지 있다(**문헌 기반**). 화면 드라이버 라이브러리가 4.0과 맞는지는 아무도 확인해 주지 않았다.

결정은 이렇게 했다. 먼저 **제조사가 검증한 3.0.7로 기준점**을 잡는다. 데모와 첫 실험이 통과하면 3.3.13, 그다음 4.0.0으로 한 계단씩 올린다. 문제가 생기면 바로 앞 계단과 비교할 수 있다.

> **감탄 노트** — "일리가 있네. 그래 확실한거 부터 잡고 나가야지." 처음 하는 분야에서 변수 두 개(내 실력, 새 버전)를 한꺼번에 늘리지 않기로 했다. 웹에서 메이저 버전 업그레이드를 기능 개발과 같은 PR에 섞지 않는 것과 같다.

## 3.3 첫 컴파일: `exit status 1`

빈 스케치를 컴파일하자 한 줄로 실패했다.

```text
exit status 1

Compilation error: exit status 1
```

원인은 보드 선택이었다. 보드를 꽂자 IDE가 USB ID(PID `0x1001`)를 보고 `ESP32 Family Device`를 **자동으로** 골랐다. 이 항목은 장치를 알아보기 위한 이름일 뿐, 빌드 대상이 아니다. Tools → Board에서 **`ESP32S3 Dev Module`**을 직접 고르자 컴파일이 됐다.

> **알게 된 점** — 웹으로 치면 브라우저가 User-Agent로 "모바일 기기"라는 것만 알아낸 상태다. 어느 빌드를 내보낼지는 따로 정해야 한다.

## 3.4 첫 업로드: `PermissionError(13)`

```text
esptool.py v4.6
A serial exception error occurred: ClearCommError failed (PermissionError(13, ...))
Failed uploading: uploading error: exit status 1
```

업로드 도구(esptool)가 칩을 다운로드 모드로 리셋하는 순간, 내장 USB가 PC에서 끊겼다가 다시 붙는다(재열거). 3.0.7에 든 esptool v4.6은 그 사이에 포트를 잃었다(**추정**). 2장에서 봤듯이 이 보드에는 자동 리셋 회로가 없다.

해결은 **수동 다운로드 모드**였다.

1. **BOOT** 버튼을 누른 채로
2. **RESET**을 눌렀다 떼고
3. **BOOT**를 뗀다

그러면 칩이 내 펌웨어를 실행하지 않고, ROM에 든 다운로드 모드에서 기다린다. 이 상태에서 업로드가 성공했다. 흥미롭게도 이 첫 한 번 이후로는 버튼 없이 자동 업로드가 됐다(**실측**, 4장).

> **질문 노트** — "리셋 했는데 검은화면 그대로야. 아 이건 펌웨어를 덮어 써서 그런가?"

맞다. 공장 데모를 지우고 시리얼만 찍는 스케치를 올렸으니, 화면을 켜는 코드가 없다. 화면은 4장에서 다시 켠다.

## 3.5 시리얼에 한 줄만 나온다

올린 스케치는 1초마다 시간과 코어 번호를 찍는 것이었다.

```cpp
void setup() {
  Serial.begin(115200);
}

void loop() {
  Serial.printf("millis=%lu core=%d\n", millis(), xPortGetCoreID());
  delay(1000);
}
```

그런데 시리얼 모니터에는 이 한 줄만 나오고 멈췄다.

```text
ESP-ROM:esp32s3-20210327
```

> **질문 노트** — "이거 뒤로 글자가 없는디?"

원인은 **`USB CDC On Boot` 설정**이었다. 앞에서 보드를 `ESP32S3 Dev Module`로 바꿀 때 Tools 메뉴의 설정이 모두 기본값으로 돌아갔고, 이 값도 `Disabled`가 됐다.

1. `ESP-ROM:...`은 칩의 ROM이 찍는 줄이다. ROM은 설정과 상관없이 내장 USB로도 출력한다
2. 스케치가 시작되면 `Serial`은 설정에 따라 출력 위치를 정한다. `Disabled`면 **UART0**으로 나간다
3. 2장에서 본 대로 UART0은 **RS485 단자**에 연결되어 있다

프로그램은 멀쩡히 돌고 있었다. 출력만 아무도 보지 않는 단자로 나가고 있었다. **stdout이 다른 곳으로 리다이렉트된 상태**다.

진단에는 빌드 크기가 도움이 됐다. 같은 스케치가 약 302KB면 CDC가 켜진 빌드이고, 약 278KB면 꺼진 빌드다(**실측**). USB 출력 코드가 빠진 만큼 작아진다. `Enabled`로 바꾸고 다시 올리자 1초마다 줄이 흘러나왔다(아래는 형식 예시).

```text
millis=1000 core=1
millis=2000 core=1
```

> **감탄 노트** — "오 나온다."

> **질문 노트** — "매번 해야해?"

아니다. IDE는 보드별로 설정을 기억한다. **보드를 바꾸면** 다시 기본값이 되니, 보드를 먼저 고르고 그다음 설정을 맞춘다.

## 3.6 Tools 메뉴, 비유로 읽기

설정 이름만으로는 의미가 와닿지 않아서 하나씩 비유를 붙였다.

| 설정 | 이 보드의 값 | 의미 | 비유 |
|---|---|---|---|
| Board | `ESP32S3 Dev Module` | 핀 이름, 칩 종류, 아래 메뉴와 기본값이 정해진다 | 빌드 타깃 프로필 |
| USB CDC On Boot | **Enabled** | `Serial`을 USB로 보낼지, UART0으로 보낼지 | stdout 리다이렉트 대상 |
| USB Mode | `Hardware CDC and JTAG` | 칩에 고정된 USB 하드웨어를 쓴다. 시리얼·JTAG·자동 리셋 | NIC 펌웨어가 처리하는 통신 |
| Flash Size | `16MB` | 플래시 용량을 링커와 업로더에 알린다 | 디스크 용량 |
| PSRAM | `OPI PSRAM` | 칩 밖의 8MB RAM을 쓸지, 버스 방식(8선)은 무엇인지 | RAM 증설과 BIOS 메모리 설정 |
| Partition Scheme | 큰 앱은 `16M Flash (3MB APP/9.9MB FATFS)` | 플래시를 앱, OTA 예비, 파일시스템으로 나눈다 | 디스크 파티션 테이블 |
| Arduino Runs On | Core 1 (기본) | `loop()`를 도는 태스크를 고정할 코어 | 스레드 CPU affinity |
| Core Debug Level | None (기본) | ESP 내부 로그 양. 올리면 출력이 늘어 관찰자 효과가 생긴다 | 로그 레벨 |

PSRAM이 왜 필수인지는 계산으로 보면 바로 보인다. 화면 한 장은 800×480×2바이트, 약 750KB다. 칩 내부 RAM은 512KB다. **PSRAM 없이는 화면 한 장도 담을 수 없다.**

USB 출력에 찍힌 `core=1`은 표의 `Arduino Runs On` 값이다. 이 숫자는 6장에서 다시 나온다.

## 알게 된 점

- 최신 버전보다 제조사가 검증한 버전으로 기준점을 먼저 잡는다. 올리는 건 한 계단씩
- IDE가 자동으로 고른 보드는 빌드 타깃이 아닐 수 있다
- 보드를 바꾸면 Tools 설정이 초기화된다. 증상은 "ROM 한 줄 뒤로 침묵"이다
- 출력이 안 보이면 프로그램이 죽었는지, 출력이 다른 데로 가는지를 먼저 가른다
