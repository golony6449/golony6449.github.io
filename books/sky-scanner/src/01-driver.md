# 1장 첫날 밤: 동글은 멀쩡했다

## 1.1 "치익" 소리만 난다

동글을 노트북에 꽂고, 가장 많이 쓰는 SDR 수신 프로그램 중 하나인 **SDR++**를 내려받아 실행했다. 첫 목표는 관제 교신이 아니라 **FM 라디오**였다. 수신이 쉽고, 신호가 세고, 무엇이 들려야 하는지 이미 알기 때문이다. 고른 방송은 KBS 쿨FM(89.1MHz)이었다.

결과는 "치익" 하는 잡음뿐이었다. 게인을 올리니 화면 아래 폭포 화면(워터폴)에 빨간 줄이 몇 개 보였고, 잡음의 결이 조금 달라졌다. 그래도 방송은 들리지 않았다.

> **감탄 노트(반대 방향)** — 이때 솔직한 심정은 "불량품 온 줄 알았다"였다. 이 장 끝에서 이 말은 "드라이버 차이가 이렇게 크구나"로 바뀐다.

## 1.2 설정부터 의심했다

이런 증상이면 먼저 설정을 의심하는 게 순서다. Claude가 SDR++의 설정 파일(`config.json`, `radio_config.json`, `rtl_sdr_config.json`)을 직접 읽어 확인했다. 결과는 모두 정상이었다.

| 항목 | 값 | 판단 |
|---|---|---|
| 주파수 | 중심 89.985MHz + 수신 창 오프셋 -885kHz = **89.1MHz** | 맞음 |
| 복조 방식 | **WFM**(방송용 광대역 FM), 대역폭 150kHz | 맞음 |
| 게인 | 22번째 단계(약 40dB) | 적당함 |
| 장치 이름 | `RTLSDRBlog Blog V4L` | ← 여기가 수상했다 |

> **알게 된 점** — SDR++ 같은 프로그램은 설정을 JSON 파일로 저장한다. 화면을 하나하나 캡처해 보여 주는 것보다, 에이전트에게 설정 파일을 읽게 하는 편이 빠르고 정확했다.

## 1.3 진짜 원인: 이름이 한 글자 달랐다

장치 이름이 **"Blog V4"가 아니라 "Blog V4L"**이었다. V4L은 V4 Lite의 줄임말이다.

RTL-SDR Blog V4는 이전 모델(V3)과 회로가 달라서, 전용 드라이버(`librtlsdr`, Windows에서는 `rtlsdr.dll`)가 동글을 **V4로 알아봐야** V4에 맞는 설정을 켠다. 그런데 이 판별이 아주 단순하다. USB 장치가 알려 주는 제품 이름이 **정확히 `"Blog V4"`와 같은지** 문자열로 비교한다.

SDR++에 들어 있던 `rtlsdr.dll`을 열어 안에 있는 문자열을 뽑아 보니 이랬다.

```text
Blog V4
RTL-SDR Blog V4 Detected
RTLSDRBlog
Found Rafael Micro R828D tuner
```

`"Blog V4L"`은 없었다. 이 드라이버에게 우리 동글은 "V4가 아닌 무언가"였고, 그래서 V4용 입력 경로 설정이 적용되지 않았다. 전파가 튜너까지 제대로 들어가지 못하니 잡음만 들렸던 것이다(**추정**: 드라이버 코드의 동작을 기준으로 한 설명이다).

> **알게 된 점** — 웹 개발로 치면 `User-Agent`를 정확히 일치하는 문자열로 비교했다가 새 브라우저 버전에서 깨지는 것과 같은 종류의 버그다. 하드웨어 세계에도 이런 일은 똑같이 있다.

## 1.4 해결: 드라이버 파일 하나 바꾸기

RTL-SDR Blog의 GitHub 저장소(`rtlsdrblog/rtl-sdr-blog`)를 보니 답이 있었다.

- 2026-03-19 커밋: **"add V4L support"**
- 이 변경이 들어간 Windows 릴리스: **V1.4.0**(2026-08-10)

V1.4.0의 `rtlsdr.dll`에는 새 문자열이 들어 있었다.

```text
Blog V4
Blog V4L
RTL-SDR Blog V4 Detected
RTL-SDR Blog V4 Lite Detected
```

할 일은 간단했다.

1. SDR++를 끈다. 실행 중에는 DLL 파일이 잠겨 있어서 바꿀 수 없다.
2. SDR++ 폴더의 `rtlsdr.dll`을 `rtlsdr.dll.bak`으로 백업한다.
3. V1.4.0의 x64 `rtlsdr.dll`을 그 자리에 복사한다.
4. SDR++를 다시 켜고 89.1MHz, WFM으로 맞춘다.

결과는 **"쿨 FM 잘 들려"**였다.

> **감탄 노트** — "야... 이게 드라이버 차이가 크구나." 같은 동글, 같은 안테나, 같은 설정인데 DLL 파일 하나로 잡음이 방송이 됐다.

한 가지 함정이 더 있었다. 필자는 V1.4.0 드라이버를 바탕화면의 `Release\x64` 폴더에 미리 받아 두었다. 그런데 **SDR++는 자기 폴더에 있는 `rtlsdr.dll`을 먼저 읽는다.** 드라이버를 받아 두는 것만으로는 소용이 없고, 프로그램 폴더의 파일을 바꿔야 한다. 이 원리는 나중에 만들 파이썬 코드에도 그대로 적용된다. 파이썬도 어느 DLL을 읽을지 명시해 줘야 한다.

## 1.5 V4와 V4L은 많이 다를까

> **질문 노트** — "V4 Lite랑 V4랑 많이 달라?"

공개 자료를 정리하면 차이는 튜너 칩과 입력 필터 정도다(**문헌 기반**).

| 항목 | V4 | V4L |
|---|---|---|
| 튜너 칩 | R828D | R828S(더 저렴) |
| 입력 필터 | 3갈래(HF / VHF / UHF) | 2갈래(HF / VHF·UHF) |
| 드라이버 | 예전 V4 드라이버로 동작 | 새 드라이버 필수 |
| 상태 | R828D 재고가 떨어져 단종 | 후속 한정판 |

수신 범위, 감도, 1PPM 온도보상 발진기 같은 기본 성능은 거의 같다고 알려져 있다. 다만 에어밴드(118~137MHz)는 FM 방송 대역(88~108MHz) 바로 위에 있다. 입력 필터가 덜 촘촘한 V4L은 근처의 강한 FM 송신소 신호가 에어밴드에 섞여 들 가능성이 V4보다 조금 클 수 있다(**추정**). 그런 증상이 보이면 FM 대역 차단 필터를 달면 된다.

> **질문 노트** — "지금 새걸 사려면 V4L밖에 없구나." RTL-SDR Blog 제품만 보면 그렇다. 다른 회사의 RTL-SDR 계열(Nooelec 등)이나 한 단계 위 제품(Airspy, SDRplay)도 있다. 나중에 ADS-B용으로 하나 더 산다면, 1090MHz 필터와 증폭기가 들어 있는 전용 동글이 낫다.

## 1.6 알게 된 점

- **"신호가 약하다"와 "드라이버가 장치를 잘못 알아본다"는 증상이 비슷하다.** 둘 다 잡음만 들리고, 게인을 올리면 무언가 조금 달라진다. 설정이 맞는데 이상하면 드라이버를 의심한다.
- **드라이버가 동글을 무엇으로 알아봤는지 확인하는 습관.** 실행할 때 `RTL-SDR Blog V4 Lite Detected` 같은 줄이 나오는지 본다.
- **프로그램마다 자기 DLL을 들고 다닌다.** SDR++, dump1090, 파이썬 바인딩 모두 각자 `librtlsdr`를 가지고 올 수 있다. 새 프로그램을 쓸 때마다 그 프로그램이 어느 드라이버를 쓰는지 확인해야 한다. 이 교훈은 6장의 ADS-B 실험과 이후 계획 전체에 "드라이버 V1.4.0 이상"이라는 제약으로 남았다.
- **에이전트에게 바이너리 안의 문자열을 뽑게 하는 것도 디버깅 도구다.** DLL을 역공학할 필요 없이, 들어 있는 문자열 목록만으로 "이 드라이버는 V4L을 모른다"를 확인할 수 있었다.
