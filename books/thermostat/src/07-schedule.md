# 7장 스케줄이라는 단어의 두 얼굴

## 7.1 목표온도와 "1시간 중 몇 분"

필자가 원한 설정은 두 가지였다.

> **질문 노트** — "목표온도랑 스케줄(1시간중 몇분 구동할지 설정)
> 이걸 메터 기기에서 설정가능할까?"

- **목표온도:** 된다. Matter 온도조절기 표준에 난방 설정온도가 있어서 SmartThings 앱에서 바로 올리고 내릴 수 있다. 조절기 화면에서 바꾼 값도 앱에 반영된다.
- **1시간 중 N분 구동:** Matter 표준에 **없다.**

후자는 한국 조절기의 **예약(반복) 모드**다. 온도와 상관없이 정해진 주기로 켜고 끈다. 방법은 셋이었다.

| 방법 | 내용 | 장단점 |
|---|---|---|
| 1. 조절기에서 설정(추천) | 화면 메뉴에 "반복 모드: 60분 중 N분" | 항상 확실하다. 앱에서는 못 바꾼다 |
| 2. 보조 엔드포인트 | 0~100% 슬라이더가 있는 장치(밝기 조절 장치)를 하나 더 만들어 %를 분으로 해석 | 앱에서 조절된다. 앱에서는 조명처럼 보이는 꼼수 |
| 3. Edge 드라이버 | SmartThings용 드라이버(Lua)를 직접 짜서 "구동 시간(분)" 같은 설정 화면을 만든다 | 가장 깔끔하다. 난이도가 높다 |

그래서 운전 방식을 **모드로 나누기로** 했다.

- **꺼짐:** 난방 안 함(최저온도 보호는 동작)
- **온도 모드:** 목표온도에 맞춰 자동으로 켜고 끄기
- **반복 모드:** 온도와 상관없이 60분 중 N분 켜기

"아침 7시에 22℃로" 같은 시간대별 목표온도는 SmartThings 루틴으로 설정온도를 바꾸면 된다.

## 7.2 AI가 헷갈린 단어

설명을 듣다가 뭔가 어긋났다. Claude가 앞에서 표준 항목을 나열하며 "주간 스케줄"을 말했었다.

> **질문 노트** — "근데 아까 너가 말한 스케줄이 60분중 n분 동작 이게 맞지? 난방비 절약을 위해서 자주 쓰는 모드더라고"

아니라는 답과 함께 정정이 돌아왔다. Claude가 헷갈리게 말했다고 했다.

| 이름 | 무엇 | 어디에 있나 |
|---|---|---|
| Matter **주간 스케줄** | "평일 7시엔 22℃, 9시엔 18℃"처럼 시간대별로 **목표온도**를 바꾼다 | Matter 표준(선택 기능) |
| 한국 조절기 **예약(반복) 모드** | 온도와 상관없이 60분 중 N분 **켠다** | Matter에 없음 |

같은 "스케줄"이라는 말이 두 생태계에서 다른 것을 가리켰다. 필자가 되묻지 않았다면 설계에 섞여 들어갔을 것이다.

반복 모드는 한국 아파트에서 난방비를 아끼려고 많이 쓰는 모드라 이 프로젝트에 꼭 넣기로 했다. 직접 만드는 만큼 개선할 여지도 있다. 반복 모드에도 **최저온도 보호**를 같이 넣어서, 너무 추워지면 정해진 시간이 아니어도 켜지게 한다.

> **웹 개발자 시선** — 도메인 용어는 생태계마다 다르다. 같은 회사 안에서도 "주문"이 팀마다 다른 테이블을 가리키는 것처럼. 그래서 이 책의 용어집(부록 A)에 "주간 스케줄"과 "반복 모드"를 따로 적었다.

## 7.3 Edge 드라이버는 나중에

> "좋아 그럼 일단 자체 펌웨어로 하고 나중에 엣지드라이버로 이전하는 걸로하자.
> 근데 드라이버 직접 만들면 앱에서 모든 조작이 가능한건 맞아?"

대부분 맞지만 **정해진 UI 부품 안에서**다(**문헌 기반**).

- Edge 드라이버는 허브에서 로컬로 돌며 기기의 Matter 항목을 읽고 쓴다. 표준에 없는 제조사 전용(커스텀) 항목도 된다.
- 커스텀 기능을 정의하면 앱에 "반복 모드", "구동 시간 N분" 같은 설정 화면이 생기고, 루틴의 조건이나 동작으로도 쓸 수 있다.
- 하지만 UI는 스위치, 슬라이더, 숫자 입력, 목록 선택 같은 정해진 부품뿐이다. 네스트 같은 원형 다이얼 그래픽은 안 된다.
- 커스텀 기능 화면은 SmartThings CLI로 따로 등록해야 하고, 앱에 반영되지 않거나 표시가 깨지는 사례가 커뮤니티에 종종 올라온다.

> "근데 우리는 슬라이더 정도면 되잖아?"

충분하다.

| 설정 | UI 부품 |
|---|---|
| 목표온도 | 표준 온도조절기 화면(드라이버 없이도 된다) |
| 운전 모드(온도/반복/꺼짐) | 목록 선택 |
| 반복 모드 구동 시간(0~60분) | 슬라이더 |
| 최저온도 보호(5~15℃) | 슬라이더나 숫자 입력 |

결정: **1단계는 자체 펌웨어(화면)에서만 설정하고, Edge 드라이버는 나중에.** 대신 펌웨어를 짤 때 설정 모델을 따로 떼어 두어, 나중에 Matter 커스텀 속성으로 옮기기 쉽게 한다. Arduino Matter 라이브러리가 커스텀 클러스터를 지원하지 않으면, 그때 ESP-IDF(esp-matter)로 옮길지 보조 엔드포인트로 우회할지 정한다.

> **웹 개발자 시선** — Edge 드라이버는 SmartThings 쪽 어댑터(플러그인)다. 기기는 그대로 두고 앱에 보이는 화면만 바꾼다. 화려한 UI는 실물 기기가 맡고, 앱은 관리자 페이지 역할을 한다.

## 알게 된 점

- 한국 조절기의 반복(예약) 모드는 Matter 표준에 없다. 표준에 없는 기능은 일단 기기에서 구현한다.
- "스케줄", "예약", "반복"처럼 흔한 단어일수록 무엇을 가리키는지 처음에 못 박는다. AI의 설명도 예외가 아니다.
- 나중에 앱으로 옮길 설정은 처음부터 모델을 분리해 둔다. 옮길 때 펌웨어를 다시 짤 필요가 없어진다.
