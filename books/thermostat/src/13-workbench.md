# 13장 격리된 작업실과 PC 단위 테스트

여기서부터 5부다. 1부부터 4부까지가 "실측이 거의 없는 설계"였다면, 5부는 **실측이 쏟아진 하루**(2026-11-24 밤 ~ 11-25 밤)의 기록이다. 이날 일감 12개가 끝났다.

## 13.1 도구가 있나부터

설계 다음 날 첫 질문은 코드가 아니라 도구였다.

> "너 아두이노 cli 도구에 접근할수 있어?"

확인해 보니 PC에는 Arduino IDE 2.x에 들어 있는 `arduino-cli.exe` v1.6.0이 있었다. 전역 `Arduino15` 폴더에는 다른 프로젝트(『웹 개발자의 ESP32 도전기』의 로봇 실험실)가 쓰는 `esp32:esp32@3.0.7` 코어가 깔려 있었다.

여기서 첫 갈림길이 나왔다. 펌웨어가 쓸 Arduino ESP32 내장 `Matter` 라이브러리는 코어 `3.1.0` 이상부터 들어 있다(**문헌 기반**). 그렇다고 전역 코어를 올리면 기존 프로젝트가 깨질 수 있다.

결정은 **프로젝트 전용 작업실**이었다.

- `%LOCALAPPDATA%\thermostat-esp32\arduino-cli.yaml`로 이 프로젝트만 쓰는 설정 파일을 만들고, 그 안에만 `esp32:esp32@3.3.12`를 설치했다.
- 보드용 라이브러리(`ESP32_Display_Panel 1.0.0`, `LVGL 8.4.0` 등)는 기존 sketchbook을 함께 쓴다.

> **웹 개발자 시선** — 전역 설치를 건드리지 않고 프로젝트별 설정을 두는 것은 Python의 `venv`나 Node의 `nvm`과 같다. 버전이 다른 두 프로젝트가 한 PC에서 서로를 깨뜨리지 않는다.

## 13.2 PC에서 도는 두뇌

6장에서 정한 원칙이 있었다. `core/`는 시간과 온도를 받아 "난방 요청 여부"를 내놓는 순수 C++로 만들고, PC에서 단위 테스트한다. 그런데 이 PC에는 보드용 크로스 컴파일러만 있고 PC용 C++ 컴파일러가 없었다. `winget`으로 WinLibs MinGW-w64(`g++ 16.2.0`)를 설치했다.

> "방금 msdn 어쩌구 설치했어?"

Microsoft 제품이 아니라 PC용 오픈소스 C++ 컴파일러라는 답이 돌아왔다. ESP32에 매번 굽지 않고, PC에서 제어 로직을 1초 만에 테스트하려고 설치한 것이다.

> **질문 노트** — "방금 msdn 어쩌구 설치했어?" → 보드용 크로스 컴파일러(`xtensa-esp32s3-elf-g++`)와 별개로, 순수 C++ 로직을 내 PC에서 바로 돌려 보는 호스트 컴파일러(`g++`)가 필요하다.

그다음 가장 작은 펌웨어 `demos/00_smoke`를 보드(`COM9`)에 올려 첫 부팅을 확인했다(**실측**).

```text
core=0.1.0 flash_mb=16 psram_bytes=8388608
```

보드 설정 문자열(FQBN)은 이렇다. 따라 할 사람을 위해 그대로 적는다.

```text
esp32:esp32:esp32s3:CDCOnBoot=cdc,USBMode=hwcdc,FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB
```

`CDCOnBoot=cdc`는 빼면 안 된다. Waveshare 4.3B는 UART0이 RS485 단자에 연결되어 있어서, USB로 시리얼 로그를 보려면 USB CDC를 켜야 한다.

## 13.3 AI 개발팀을 굴리다

뼈대가 서자 필자는 일감을 한꺼번에 돌려 보자고 했다.

> "지금 있는 티켓 전부 agy 모드의 워크플로우로 작업해보자 239는 일단 패스하고 넘어가줘."

진행 탭을 지켜보던 필자가 물었다.

> "근데 왜 이거 다 주니어가 아니고, 제미나이야?"

역할을 다시 정리했다.

| 역할 | 맡은 일 | 누가 |
|---|---|---|
| 설계·계획 PL | 계획과 인터페이스를 정한다 | Gemini(Antigravity) |
| 실행 PL | 워크트리를 만들고 PR을 오케스트레이션한다 | 경량 모델 |
| 주니어 | 일감 전용 워크트리(`feature/SCRUM-xxx`)에서 코드를 쓴다 | DeepSeek |
| QA | 코드를 검토한다 | Qwen |

여러 일감을 동시에 돌리자 현실의 벽 세 개를 만났다.

1. **Windows 가상 메모리 한도(`WinError 1455`).** ESP32 크로스 컴파일 3건이 동시에 도는데 4번째 에이전트를 띄우자 페이징 파일 한도에 걸렸다. 동시 `arduino-cli` 빌드는 1~2개로 줄였다.
2. **보안 스캐너 오탐(`secret_detected`).** `library.properties`에 적은 작성자 이름이 정확히 16자라, QA 도구의 비밀값 정규식(`auth` + 16자 이상 대입)에 걸렸다. 작성자 표기를 짧게 바꿨다.
3. **외부 검토 API 한도(HTTP 429).** 중간에 Qwen API 예산이 바닥나, 그 뒤 PR은 PL이 계획의 "검토할 점"만 직접 봤다.

일감 8개를 PR로 만드는 데 든 DeepSeek 비용은 약 0.52달러였다(**실측**).

> **웹 개발자 시선** — AI 여러 명을 동시에 굴리면 빠르지만, 컴파일러 3개가 동시에 돌면 노트북 메모리가 먼저 항복한다. 임베디드 크로스 컴파일은 웹 번들러보다 훨씬 무겁다.

## 13.4 하드웨어 없이 만든 두뇌

세 모듈을 "보드가 필요한가"로 잘라 동시에 만들었다. 10장의 일감 그래프가 그대로 효과를 낸 장면이다.

| 일감 | 모듈 | 내용 | 테스트(**실측**) |
|---|---|---|---|
| SCRUM-234 | `src/core/` | 순수 C++17 제어 상태 머신 | 호스트 16/16 |
| SCRUM-235 | `src/sensor/` | 이동평균(5샘플), 이상값·급변 판단, ISO-8601 파서, 홈서버 JSON 파서, 원격→보드 센서 자동 전환, "방금 / N분 전" 문구 | 호스트 25/25 |
| SCRUM-236 | `demos/02_io` | SHT40 드라이버, PCF85063A RTC + NTP 시계, 홈서버 HTTP 클라이언트 | 호스트 헬퍼 12/12 |

`core/`를 만들며 10장에서 찾은 빈틈도 닫았다. "반복 모드가 60분 중 60분이면 70분 데드맨이 정상 난방을 끊지 않나?" **반복 모드(N=60 포함)와 최저온도 보호의 연속 난방에도 온도 모드와 같은 50분 유지 신호를 적용**하기로 했다. 그리고 안전 우선순위를 코드로 못 박았다.

1. 센서 이상이면 즉시 정지(반복 모드는 경고만)
2. 최저온도 보호(최소 꺼짐 시간도 무시)
3. 모드 판단(꺼짐 / 히스테리시스 / 60분 중 N분)
4. 최소 켜짐·꺼짐 5분
5. 50분 넘게 연속 난방이면 유지 신호

센서 쪽 ISO-8601 파서는 타임존 설정에 기대지 않게 만들었다. 날짜를 일수로 바꾸는 계산은 Howard Hinnant의 달력 공식을 썼다. 급변 판단은 "5℃ 이상 튄 값이 3번 연속 나오면 진짜 변화로 인정"이다.

SHT40은 아직 사지 않았다. 그래서 보드에서는 **센서가 없어도 멈추지 않는지**만 봤다(**실측**). I2C 스캔에 IO 확장 칩 CH422G(`0x20`~`0x27`)만 잡혔고, 펌웨어는 `sht40=0`으로 표시하고 넘어갔다. 보드의 RTC 배터리 스위치가 꺼져 있어 `rtc=n/a`가 뜨는 것도 확인했다.

> **웹 개발자 시선** — 하드웨어가 도착하지 않아도, 프로토콜(CRC-8, JSON 파서, 상태 머신)을 순수 함수로 빼 두면 테스트 53개를 먼저 통과시킬 수 있다. API 서버가 아직 없을 때 목(mock) 데이터로 프런트엔드와 도메인 로직을 먼저 완성하는 것과 같다.

## 알게 된 점

- 전역 도구를 올리기 전에, 그 도구를 쓰는 다른 프로젝트부터 떠올린다. 프로젝트 전용 설정 파일 하나면 둘 다 산다.
- 보드에 의존하지 않는 코드는 PC 컴파일러 하나로 1초 만에 테스트된다. 이 테스트들이 17장에서 통합할 때 그물이 된다.
- 자동화 파이프라인에는 "외부 검토자가 멈췄을 때"의 대체 규칙이 있어야 작업이 멈추지 않는다.
- 동시에 돌릴 수 있는 일의 상한은 일감 그래프가 아니라 노트북 메모리가 정할 때도 있다.
