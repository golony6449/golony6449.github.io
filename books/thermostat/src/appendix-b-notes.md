# 부록 B. 질문 노트와 감탄 노트

본문에 흩어진 노트를 한곳에 모았다. 따옴표 안은 실제로 입력한 그대로다. 가린 부분은 `[대괄호]`로 표시했다. 1~11장은 2026-11-24, 12~18장은 2026-11-25, 19~21장은 2026-11-26의 일이다.

## 질문 노트

| 장 | 질문 | 짧은 답 |
|---|---|---|
| 1 | "채팅이 나을까 아님 코드에서 말하는게 나을까?" | 구상은 채팅, 구현은 Claude Code. 정리본을 넘긴다 |
| 2 | "이 배선도 맞지?" | 직접 만든 조절기와 릴레이 사이엔 선이 없다. 무선으로 잇는다 |
| 2 | "아 저게 중성선이 없는 전형적인 구성이야?" | 옛날 전등 스위치와 같다. L선만 끊었다 잇는다 |
| 3 | "왁스 방식 구동기는 아날로그야?" | 0 아니면 100. 아날로그는 시간 비례 제어로 흉내 낸다 |
| 3 | "A안도 220v를 다뤄야하는건 똑같지 않아?" | 맞다. 다른 건 위험이 아니라 작업 난이도 |
| 4 | "커플러? 를 뭐라고 부르더라?" | 전선 커넥터. 벽 박스용으로는 2구 레버식 |
| 5 | "우리 매터 장치가 있어?" | ESP32 보드가 펌웨어로 Matter 장치가 된다. 허브는 필요 |
| 5 | "내 기기도 지그비나 매터 칩이 달려있어야하는거 아냐?" | Matter는 IP 기반. Wi-Fi 보드로 된다 |
| 6 | "온도조절기 표준에는 어떤 설정들이있어?" | 기본은 현재 온도·설정온도·모드·작동 상태. 앱에 다 보이는지는 시험 필요 |
| 7 | "이걸 메터 기기에서 설정가능할까?" | 목표온도는 표준, 60분 중 N분은 표준에 없다 |
| 7 | "스케줄이 60분중 n분 동작 이게 맞지?" | 아니다. Matter 스케줄은 시간대별 목표온도, N분은 반복 모드 |
| 7 | "드라이버 직접 만들면 앱에서 모든 조작이 가능한건 맞아?" | 정해진 UI 부품 안에서. 슬라이더면 충분 |
| 8 | "그걸 온도센서로 연동시킬수있을까?" | 홈서버가 토큰을 들고 값을 HTTP로 내주면 된다 |
| 9 | "자동꺼짐은 스마트싱스 루틴으로 거는거야?" | 원칙은 플러그 자체 기능. 현실은 루틴 + 홈서버 알림 |
| 10 | "좀더 동시에 진행할수있도록 일감 설계해볼래?" | 순수 로직과 보드 I/O를 나누고, UI는 가짜 상태로 먼저 |
| 11 | "꺼졌을 때 0V, 켜졌을 때 220V 아냐?" | 스위치 양 끝을 재면 반대다 |
| 12 | "왁스형 구동기는 대부분 220v 로 구동되더라?" | 대부분 220V, NC가 흔하다. 하지만 NO도 24V도 있다. 라벨부터 본다 |
| 12 | "오픈형이면 뭐가 열려 있다는 거야?" | 전기 접점이 아니라 밸브. 전기가 없을 때 열려 있다 |
| 12 | "벽에서 오는 선으로 콘센트를 만들면 그냥 220V 아냐?" | 조절기를 거친 선이면 조절기를 따라 죽는다. 테스터로 가린다 |
| 13 | "방금 msdn 어쩌구 설치했어?" | PC에서 C++ 단위 테스트를 돌릴 MinGW-w64 `g++`다 |
| 13 | "근데 왜 이거 다 주니어가 아니고, 제미나이야?" | 계획은 PL(Gemini), 코드는 주니어(DeepSeek), 검토는 QA(Qwen) |
| 14 | "이거 다크모드야? 목표온도 +/- 버튼이 잘 안보여." | 라벨 글자색을 안 줘서 기본 검정 글자가 묻혔다 |
| 15 | "NVS가 뭐야?" | ESP32의 `localStorage`. 수명 때문에 디바운스를 건다 |
| 16 | "네트워크를 찾을수 없다는데?" | ESP32-S3는 2.4GHz만 쓴다. BLE는 지나가도 Wi-Fi에서 막힌다 |
| 17 | "근데 화면이 까맣게 나와" | 모듈별 데모에는 화면이 없다. 합치는 게 통합이다 |
| 17 | "왜이렇게 오래걸려? 좀 있으면 1시간이야." | 안 쓰는 LVGL 예제 500개와 `#include <Matter.h>` 위치 |
| 18 | "시간 갱신용 api도 하나 만들까?" | NTP가 막힐 때의 예비 시계 |
| 18 | "253은 근데 레포를 봐야 알수있잖아" | 다른 레포의 에이전트가 읽으니 API로 준다 |
| 18 | "252 253 동시진행 가능할까?" | 같은 파일이라도 소유 범위와 공통 규칙을 나누면 된다 |
| 19 | "화면 일부가 깨져보이다가 돌아오곤 하는데 SW 이슈일수있을까?" | SW 맞다. 다만 우리 코드가 아니라 화면 드라이버였다 |
| 19 | "그래도 흔들리는데? … 근데 다시 해보니까 정상이네?" | 들쭉날쭉함 자체가 단서. 두 상태를 오가는 버그였다 |
| 21 | (A인가 B인가) "A에 가까워" | 한 프레임 어긋남. 덜 그리면 준다 |

## 감탄 노트

| 장 | 장면 |
|---|---|
| 1 | "아하 넘길수있구나." 채팅에서 한 설계를 통째로 코드 도구로 넘긴다 |
| 2 | 건전지가 없다는 사실 하나로 조절기가 220V에서 전기를 빌려 쓴다는 걸 추리했다 |
| 5 | "아아 와이파이 베이스구나 첨알았어." 이미 가진 Wi-Fi 보드가 그대로 Matter 기기가 된다 |
| 5 | "4B"가 4MB인 줄 알고 걱정했는데, 로봇 실험실 보드가 16MB 플래시로 넉넉했다 |
| 9 | "저 기능 데드맨 스위치 맞잖아." 웹에서 쓰던 하트비트·TTL을 난방 안전장치에서 알아봤다 |
| 14 | 실물 화면에서 찾은 네 건을 한 번에 고쳐 올렸을 때: "잘 되네." |
| 16 | "상태 있어. 70분 설정도 가능해." 가장 큰 위험이 순정 Matter로 한 번에 통과했다 |
| 16 | 등록이 끝나자 BLE 메모리가 돌아와 남은 RAM이 97KB에서 169KB로 늘었다 |

| 17 | 통합 펌웨어 첫 부팅이 패닉 없이 `already commissioned` → `UI ready` → `RTC saved`까지 한 번에 지나갔다 |
| 19 | 설정 저장 대기를 5초에서 15초로 바꾸자 흔들림이 "1회 14초, 2회 14초"로 따라왔다. 숫자 하나가 가설 셋을 정리했다 |
| 20 | 몇 초씩 가던 흔들림이 코드 한 줄 없이 코어 버전 하나로 사라졌다: "아까보다는 훨신 나은데" |
