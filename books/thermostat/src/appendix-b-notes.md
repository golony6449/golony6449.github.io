# 부록 B. 질문 노트와 감탄 노트

본문에 흩어진 노트를 한곳에 모았다. 따옴표 안은 실제로 입력한 그대로다. 가린 부분은 `[대괄호]`로 표시했다. 모두 2026-11-24의 일이다.

## 질문 노트

| 장 | 질문 | 짧은 답 |
|---|---|---|
| 1 | "채팅이 나을까 아님 코드에서 말하는게 나을까?" | 구상은 채팅, 구현은 Claude Code. 정리본을 넘긴다 |
| 2 | "이 배선도 맞지?" | 직접 만든 조절기와 릴레이 사이엔 선이 없다. 무선으로 잇는다 |
| 2 | "아 저게 중성선이 없는 전형적인 구성이야?" | 옛날 전등 스위치와 같다. L선만 끊었다 잇는다 |
| 3 | "왁스 방식 구동기는 아날로그야?" | 0 아니면 100. 아날로그는 시간 비례 제어로 흉내 낸다 |
| 3 | "A안도 220v를 다뤄야하는건 똑같지 않아?" | 맞다. 다른 건 위험이 아니라 작업 난이도 |
| 4 | "커플러? 를 뭐라고 부르더라?" | 전선 커넥터. 벽 박스용으로는 2구 레버식 |
| 5 | "우리 매터 장치가 있어?" | ESP32 보드가 펌웨어로 Matter 장치가 된다. 허브는 필요 |
| 5 | "내 기기도 지그비나 매터 칩이 달려있어야하는거 아냐?" | Matter는 IP 기반. Wi-Fi 보드로 된다 |
| 6 | "온도조절기 표준에는 어떤 설정들이있어?" | 기본은 현재 온도·설정온도·모드·작동 상태. 앱에 다 보이는지는 시험 필요 |
| 7 | "이걸 메터 기기에서 설정가능할까?" | 목표온도는 표준, 60분 중 N분은 표준에 없다 |
| 7 | "스케줄이 60분중 n분 동작 이게 맞지?" | 아니다. Matter 스케줄은 시간대별 목표온도, N분은 반복 모드 |
| 7 | "드라이버 직접 만들면 앱에서 모든 조작이 가능한건 맞아?" | 정해진 UI 부품 안에서. 슬라이더면 충분 |
| 8 | "그걸 온도센서로 연동시킬수있을까?" | 홈서버가 토큰을 들고 값을 HTTP로 내주면 된다 |
| 9 | "자동꺼짐은 스마트싱스 루틴으로 거는거야?" | 원칙은 플러그 자체 기능. 현실은 루틴 + 홈서버 알림 |
| 10 | "좀더 동시에 진행할수있도록 일감 설계해볼래?" | 순수 로직과 보드 I/O를 나누고, UI는 가짜 상태로 먼저 |
| 11 | "꺼졌을 때 0V, 켜졌을 때 220V 아냐?" | 스위치 양 끝을 재면 반대다 |

## 감탄 노트

| 장 | 장면 |
|---|---|
| 1 | "아하 넘길수있구나." 채팅에서 한 설계를 통째로 코드 도구로 넘긴다 |
| 2 | 건전지가 없다는 사실 하나로 조절기가 220V에서 전기를 빌려 쓴다는 걸 추리했다 |
| 5 | "아아 와이파이 베이스구나 첨알았어." 이미 가진 Wi-Fi 보드가 그대로 Matter 기기가 된다 |
| 5 | "4B"가 4MB인 줄 알고 걱정했는데, 로봇 실험실 보드가 16MB 플래시로 넉넉했다 |
| 9 | "저 기능 데드맨 스위치 맞잖아." 웹에서 쓰던 하트비트·TTL을 난방 안전장치에서 알아봤다 |

이 표는 프로젝트가 진행되는 동안 계속 늘어난다.
