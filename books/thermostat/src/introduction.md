# 서문: 보일러 온도조절기인 줄 알았다

## 시작

2026년 11월 24일, 우리 집 난방을 삼성 SmartThings에 붙여 보기로 했다. 구글 네스트처럼 동그란 화면에 온도가 뜨고, 휴대폰 앱에서 목표 온도를 바꾸고, 외출하면 알아서 난방을 줄이는 온도조절기를 직접 만들 생각이었다.

처음에는 이 프로젝트를 "보일러 온도조절기 연동"이라고 불렀다. 그런데 설계 대화를 몇 번 주고받고 나서야 알았다. **우리 집에는 보일러가 없다.** 아파트 지역난방이라, 집에 있는 건 바닥 배관으로 들어오는 온수를 열고 닫는 밸브와 그 밸브를 움직이는 작은 구동기뿐이었다. 이 책의 제목은 거기서 왔다.

필자는 웹 개발자다. HTTP, JSON, REST API, 캐시, 헬스체크는 익숙하다. 하지만 중성선, 왁스 구동기, 최소 부하, Matter 클러스터는 처음이다. 이 사이트의 『웹 개발자를 위한 임베디드 입문』에서 통신 이론을, 『웹 개발자의 ESP32 도전기』에서 보드 다루는 법을 익혔다. 이 책은 그 다음 단계다. **IoT를 해 보려고 임베디드에 들어온 웹 개발자가, 실제로 집에서 쓸 물건을 만드는 토이 프로젝트 개발기**다.

## 이 책은 정답집이 아니다

실제로 겪은 순서대로 쓴다. 이 책의 1부는 코드 한 줄 없이 채팅 하루로 끝난다. 그 하루 동안 배선도가 네 번 바뀌었고, AI의 설명을 되물어 바로잡은 일이 몇 번 있었고, 설계를 다 마치고 일감 17개까지 등록한 뒤에 싱크대 문을 열었더니 전제 하나가 무너졌다. 이 책은 그런 장면을 숨기지 않는다.

각 장은 대체로 세 덩어리로 이루어진다.

1. **무엇을 했나:** 실제로 한 일과 그 순서
2. **어디서 헤맸나:** 처음에 생각한 것과 실제로 밝혀진 것
3. **알게 된 점:** 다음에 같은 일을 하는 사람(그리고 미래의 나)에게 남기는 것

## 일하는 방식

설계는 Claude 앱(채팅)에서 했다. 부품과 구조를 정하는 일은 이야기를 주고받는 쪽이 빨랐다. 설계가 끝나자 대화 원문을 통째로 Claude Code에 넘겨 집필 노트를 만들고, 개발 기준 문서(`CLAUDE.md`)를 레포에 넣고, 개발 순서를 Jira 일감으로 쪼갰다. 구현은 그 일감을 하나씩 처리하며 진행한다.

- 설계 대화: Claude 앱
- 기록, 기준 문서, 일감 쪼개기: Claude Code
- 구현: Claude Code와 구현 담당 AI(DeepSeek), 코드 검토는 Qwen

## 웹 개발자 시선

하드웨어나 스마트홈 개념이 처음 나올 때마다 웹 쪽 비유를 붙인다. 필자는 "Matter over Wi-Fi"라는 말보다 "Matter는 HTTP 같은 응용 계층 규약이고 Wi-Fi는 그 아래 전송 계층"이라는 설명을 훨씬 빨리 이해했다. 데드맨 스위치는 TTL 리스로, 원격 센서의 신선도 판단은 캐시의 `Last-Modified`로 읽힌다. 비유는 정확한 정의가 아니라 감을 잡기 위한 손잡이다.

## 질문 노트와 감탄 노트

모르는 것이 많았다. 실제로 던진 질문은 **질문 노트**로, "오, 그렇구나" 싶었던 순간은 **감탄 노트**로 남겼다. 따옴표 안은 실제로 입력한 그대로다. 오타도 고치지 않았다. 부록 B에 모아 두었다.

> **질문 노트** — 실제로 던진 질문과, 그때 들은 설명이다.

> **감탄 노트** — 실제로 놀랐던 장면이다.

## 근거 표기

이 사이트의 다른 책과 같은 원칙을 쓴다. 확인하지 않은 값을 단정하지 않는다.

| 표기 | 뜻 |
|---|---|
| **실측** | 필자가 실물로 직접 보거나 잰 것이다 |
| **문헌 기반** | 제조사 문서, 공식 문서, 커뮤니티 글에서 가져왔고 직접 확인하지는 않았다 |
| **추정** | 근거는 있지만 확정은 아니다 |
| **확인 필요** | 아직 검증하지 못했다 |

1부에서 3부까지는 설계 이야기라 **실측이 거의 없다.** 하드웨어에 관한 말은 대부분 필자의 기억이거나 문헌이다. 그 기억이 실물과 어긋난 장면이 11장이다.

## 무엇을 구체적으로 쓰고, 무엇을 가리나

이 책은 독자가 따라 할 수 있게 쓴다. 그래서 **ESP32 보드, 센서, 부품, 라이브러리는 모델명까지 구체적으로 쓴다.** 반대로 사는 곳과 집에 있는 기기처럼 필자를 특정할 수 있는 정보는 가린다. 지역은 "구축 아파트" 정도로만 적고, SmartThings 허브는 기기 종류를 밝히지 않고 "허브"라고만 쓴다. 따옴표 안에서 가린 부분은 `[대괄호]`로 표시했다.

## 220V에 대해

이 프로젝트는 220V로 움직이는 난방 구동기를 다룬다. 이 책의 원칙은 **220V는 인증받은 완제품(스마트 플러그 등)에 맡기고, 직접 만드는 회로는 USB 전원 쪽에만 둔다**는 것이다. 책에 나오는 전기 작업은 "따라 하라"가 아니라 "필자가 한 일"이다. 차단기를 내리고, 검전기로 전기가 끊겼는지 확인하고, 조금이라도 자신이 없으면 전기기사에게 맡긴다. 이 책은 전기 공사 안내서가 아니다.

## 장비

| 항목 | 내용 |
|---|---|
| 난방 | 아파트 지역난방, 바닥난방. 온도조절기 1개 = 집 전체 1구역 |
| 구동기 | 왁스(열동)식, 220V, 켜짐/꺼짐. 라벨(전압, W, NO/NC)은 **확인 필요** |
| 프로토타입 보드 | Waveshare **ESP32-S3-Touch-LCD-4.3B** |
| 모듈 | ESP32-S3-WROOM-1-N16R8 (LX7 듀얼 코어 240MHz, 플래시 16MB, PSRAM 8MB, Wi-Fi 2.4GHz, BLE 5) |
| 화면 | 4.3인치 800×480 RGB LCD, 정전식 5점 터치(GT911) |
| 그 밖 | I2C(GPIO8 SDA, GPIO9 SCL), RTC, RS485, CAN, 절연 DI/DO, IO 확장 칩 CH422G |
| 온도 센서(예정) | SHT40(I2C), 보드에서 떨어뜨려 장착 |
| 최종 기기 후보 | M5Stack M5Dial(ESP32-S3, 원형 화면 + 다이얼) 또는 위 보드를 벽걸이 패널로 |
| 펌웨어 | Arduino ESP32 코어 3.x + 내장 Matter 라이브러리(Matter over Wi-Fi), UI는 LVGL |
| 스마트홈 | 삼성 SmartThings, Matter 지원 허브 |
| 홈서버 | SmartThings API 토큰을 24시간마다 갱신하는 자작 서버(Home-Dashboard) |

프로토타입 보드는 『웹 개발자의 ESP32 도전기』에서 하루 전(2026-11-23)에 도착해 초기불량 점검을 마친 그 보드다. 모듈 품번과 메모리 크기는 그 책에서 **실측**으로 확인했다.

이 책은 프로젝트와 함께 자란다. 구현이 진행될 때마다 장이 늘어난다.
